Behavior and limitations

vibetest-daq enables all five current channels, uses the device constants in daq.py, 1 s blocks, 100 mV/g sensitivity, 0.004 A IEPE current, and prefix vib. It cannot select channels or override those values with command-line flags. Use the GUI when those settings need interactive control.

vibetest-daq [OPTIONS]
vibetest-daq --help
OptionDefaultMeaning
-d, --duration SECONDSUntil Ctrl+CRequests stop once elapsed wall time reaches the value. Reads are block-based, so a positive duration is effectively rounded up to complete one-second blocks.
-o, --output DIRvibration_dataOutput directory, created on first write.
-r, --rate HZ5,000Requested sample rate. The CLI does not impose the GUI's numeric range; invalid hardware values fail during DAQ configuration.
-f, --format csv|hdf5csvOutput container.
-m, --metadata-file PATHnoneUTF-8 JSON containing system metadata and channel overrides.

Examples

# About 60 one-second files at 5 kHz
vibetest-daq --duration 60 --rate 5000 --output .\test_data

# Run until Ctrl+C and write HDF5
vibetest-daq --format hdf5 --output D:\data\long_run

# Add metadata and position calibration
vibetest-daq --duration 10 --metadata-file .\metadata.json

Ctrl+C sets a graceful-stop flag. The active block completes and pending files are written before exit; wait for Acquisition stopped..

Metadata JSON schema

The file has optional system and channels objects. Channel keys must exactly match a current logical label. Unknown keys are ignored. Missing values use defaults.

{
  "system": {
    "test_id": "FAN-SWEEP-001",
    "dut_make": "Acme",
    "dut_model": "VX-10",
    "dut_serial": "SN-0042",
    "test_stand": "Stand A",
    "operator": "J. Smith",
    "location": "Lab 3",
    "notes": "Baseline; position calibration CAL-2026-17"
  },
  "channels": {
    "Mod1_Ch0": {
      "sensor_type": "accelerometer",
      "units": "g",
      "bandwidth_hz": "3000",
      "axis": "X",
      "location": "top plate",
      "sensor_serial": "A123"
    },
    "Pos_Ch0": {
      "sensor_type": "position",
      "units": "mm",
      "scale": 0.5,
      "offset": 0.0,
      "location": "stage edge",
      "sensor_serial": "P456"
    }
  }
}

Allowed channel override fields are sensor_type, units, bandwidth_hz, axis, location, sensor_serial, scale, and offset. Scale/offset must be JSON numbers. Position units g are rejected and reset to um. JSON syntax or file errors are reported by the argument parser before acquisition.

Python orchestration API

vibetest_daq.session.capture_session runs a finite acquisition and returns DaqCaptureResult(files, actual_sample_rate_hz, block_count, errors). It accepts output directory, duration, prefix, rate, block duration, format, metadata file, system metadata, and channel overrides. A direct dictionary overrides the same value loaded from JSON. Duration is converted to ceil(duration / block_duration) complete files, so recorded time may exceed the request.

from vibetest_daq.session import capture_session

result = capture_session(
    output_dir="test_data",
    duration_s=5,
    sample_rate_hz=5000,
    system_metadata={"test_id": "FAN-SWEEP-001"},
)
if result.errors:
    raise RuntimeError(result.errors)
