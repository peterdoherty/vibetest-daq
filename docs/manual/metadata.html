Recommended practice

Every field is optional to the software, but a test without context may be unusable later. Assign a unique Test ID before each run and use the same identifier in the lab log, analysis, and report. Metadata is copied into every block file, so each file remains identifiable when separated from its directory.

What appears in files

Nonempty system fields become CSV comment lines or HDF5 root attributes named Test ID, DUT Make, DUT Model, DUT Serial Number, Test Stand, Operator, Location, and Test Notes. CSV notes are collapsed to one line with nonempty source lines separated by | ; HDF5 preserves line breaks.

# Test ID: FAN-SWEEP-001
# DUT Make: Acme
# DUT Model: VX-10
# DUT Serial Number: SN-0042
# Test Notes: Baseline | 22 C ambient | position calibration CAL-2026-17

Summary and persistence

The Acquire tab summary updates as fields and channel axis/location values change. Notes longer than 120 characters are shortened only in this display. GUI metadata persists between application launches and is saved on Start or normal close.

Persistence is convenient and hazardous. The application does not know that the DUT or calibration changed. Review Test ID, DUT serial, Notes, channel serials, locations, and scale/offset before every run.

What metadata does not capture

The output currently does not store requested rate, IEPE excitation, position Scale/Offset, device names, disabled channels, software version, or operator changes during a run. Put critical configuration references in Notes and retain the project configuration/test log.
