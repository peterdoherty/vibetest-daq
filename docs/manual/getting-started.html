Getting Started

Install the runtime, identify the hardware, and make a short commissioning recording.

Requirements

ItemRequirement
ComputerWindows is the normal deployment platform for NI MAX and NI-DAQmx hardware use.
Python3.10 or newer, 64-bit recommended.
NI softwareNI-DAQmx driver and NI Measurement & Automation Explorer (NI MAX).
Python packageThis repository and its dependencies: h5py, isw-instruments, nidaqmx, NumPy, and PySide6.
HardwareCompatible cDAQ chassis/modules and properly wired IEPE accelerometer and/or analog-output position sensors.
Before connecting sensors: Power down or place the DUT in a safe state. Observe the sensor, module, grounding, and connector requirements. Do not connect an ordinary voltage source to a channel while IEPE excitation is enabled unless the source is designed to tolerate it.

1. Install and verify NI-DAQmx

  1. Install NI-DAQmx with NI MAX, then reboot if the installer requests it.
  2. Connect and power the cDAQ chassis.
  3. In NI MAX, expand Devices and Interfaces. Record the exact module names, such as cDAQ2Mod1 and cDAQ2Mod2.
  4. Run NI MAX self-test on the chassis and modules. Resolve failures before using Vibetest DAQ.
  5. Use an NI MAX test panel, when appropriate, to confirm a small signal can be read from each intended input.

Renaming devices in NI MAX changes the names that must be entered in Vibetest DAQ. Names are case-sensitive identifiers, not chassis slot descriptions.

2. Install Vibetest DAQ

Open PowerShell in the repository root. Create and activate an isolated environment:

py -3.10 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e .

If PowerShell blocks activation, either follow your organization's execution-policy procedure or invoke the environment directly, for example .venv\Scripts\vibetest-daq-gui.exe. Development tools are optional:

python -m pip install -e ".[dev]"

Confirm that the entry points are installed:

vibetest-daq --help
vibetest-daq-gui

3. Configure the current hardware names

On the GUI Acquire tab, set Module 1 device to the module supplying Mod1_Ch0–Ch2, and Module 2 device to the module supplying Pos_Ch0–Ch1. The shipped defaults are cDAQ2Mod1 and cDAQ2Mod2. Module 3 is not used by the active channel map.

The CLI does not accept device-name options. Its names are the DEFAULT_MODULE_1 and DEFAULT_MODULE_2 constants in src/vibetest_daq/daq.py; change the deployment configuration/code if they do not match NI MAX.

4. Make a safe commissioning recording

  1. Create an empty local output folder with enough free space.
  2. Open the Channels tab. Enable one known accelerometer channel; disable unused channels. Confirm its axis, location, sensor serial, and units.
  3. On Acquire, enter the sensor's calibrated sensitivity and approved IEPE current. Use 5,000 Hz, a 1 s block, CSV, Continuous off, and File count 3.
  4. With the DUT still in a safe state, press Start. Apply only a small, safe stimulus to the sensor.
  5. Confirm the state becomes Recording, the actual rate appears, the level changes, and three files are written.
  6. Open the newest CSV in a text editor. Confirm its Test ID, sample rate, enabled channel name, units, and plausible values.
Do not treat a moving level bar as calibration proof. It only displays the maximum absolute value in the most recently completed block. Complete the range and calibration checks in the Operating Procedure.
