Purpose and audience

Vibetest DAQ records synchronized acceleration and analog position measurements. This manual assumes basic laboratory safety and undergraduate-level measurement knowledge, but no prior experience with this program. A new operator should begin with Getting Started, then follow the Operating Procedure for the first test.

Measurement responsibility: The program cannot tell whether a sensor is mounted correctly, whether its sensitivity or position calibration is correct, or whether the test is safe. Have the test owner approve the mechanical setup, sensor ranges, and operating limits before energizing the device under test (DUT).

What the program does

The GUI (vibetest-daq-gui) provides interactive settings, metadata, channel selection, and block-level peak meters. The CLI (vibetest-daq) provides fixed one-second blocks for scripts and unattended runs. Both use the same acquisition and file-writing code and can write CSV or HDF5.

Samples are acquired continuously in fixed-duration blocks. Each completed block becomes one timestamped file. Pressing Stop is graceful: the current hardware read finishes, queued files are written, and then the session ends. With a long block duration, stopping can therefore take about one block plus processing time.

Concepts you need

Acceleration and IEPE

An IEPE accelerometer needs constant-current excitation. The configured sensitivity in mV/g converts its electrical signal to acceleration in g. Use the calibrated sensitivity for the connected sensor. The one GUI sensitivity value applies to all enabled accelerometer channels, so sensors with materially different sensitivities should not be mixed in one acquisition.

Position scaling

Position inputs are voltage channels. For each position channel the program applies position = scale × voltage + offset. Scale is in engineering units per volt and offset is in the same engineering units. The default scale of 1 and offset of 0 are placeholders, not a calibration.

Sample rate and bandwidth

A sample rate of Fs has a Nyquist frequency of Fs/2, but a practical test should also respect the sensor and module bandwidth and leave margin below Nyquist. For example, a 5 kHz rate cannot support analysis above 2.5 kHz. Always use the actual rate stored in the output file; hardware may adjust the request.

Time

Files use UTC block timestamps and POSIX epoch seconds. The sample time column is generated from the block start and actual sample rate. Synchronize the acquisition computer's clock before tests that must correlate with other systems.
