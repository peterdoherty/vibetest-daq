Troubleshooting

Diagnose installation, DAQ, data-quality, and output problems without risking the test article.

Start with these checks

  1. Make the DUT safe; do not troubleshoot live moving/high-energy hardware unless the approved procedure requires it.
  2. Copy the complete error message and NI-DAQmx error number.
  3. Confirm the virtual environment with python -c "import sys; print(sys.executable)".
  4. Confirm the chassis/modules pass NI MAX self-test and their exact names match the configuration.
  5. Repeat with one known sensor and one enabled channel, short one-second blocks, and a local output directory.

Installation and launch

Command not found

Activate the environment used for installation, or run .venv\Scripts\vibetest-daq-gui.exe. Reinstall with python -m pip install -e . and verify python -m pip show vibetest-daq.

NI-DAQmx or nidaqmx unavailable

The Python package and NI driver are separate. Install a compatible NI-DAQmx driver, reboot if requested, confirm hardware in NI MAX, and then reinstall the project environment. A Python import succeeding does not prove the driver/hardware path works.

isw-instruments not available

The shared NICDaqTask dependency failed to import. Run python -m pip show isw-instruments in the same environment, then reinstall project dependencies. If your organization supplies this package from a private source, use its approved installation instructions.

PySide6 / Qt error

Confirm Python 3.10+ and python -m pip show PySide6. The CLI can help isolate whether the fault is GUI-only, but do not start a real acquisition merely as an import test.

Hardware and configuration

Unknown device or physical channel

  1. Copy names exactly from NI MAX.
  2. For the GUI, Module 1 supplies acceleration and Module 2 supplies position in the current map; Module 3 is unused.
  3. For CLI, update the deployment constants in daq.py; GUI settings do not affect CLI.
  4. Check that the expected module type is actually installed at the named device and its ai terminals exist.

Resource reserved / device busy

Close NI MAX test panels and other programs/tasks using the same module. Stop the previous Vibetest acquisition and wait for Idle. If a crashed process retained resources, close it; power-cycle hardware only according to lab procedure.

Requested rate fails or actual rate differs

Mixed modules and their clock constraints determine supported rates. Choose a rate supported by the complete task. Small adjustment is normal; files contain the actual rate. A configuration error before rate confirmation means the requested combination was not accepted.

Stop seems slow

Stop is checked between full block reads. Wait at least the selected block duration plus processing time. Use shorter blocks when responsive stopping matters. Do not unplug the chassis to force a stop.

Signals and scaling

Acceleration is zero or implausible

  • Verify the channel is enabled and wired to the correct Module 1 ai terminal.
  • Verify approved nonzero IEPE current and compatible sensor polarity/wiring.
  • Check the shared mV/g sensitivity against the calibration sheet.
  • Test the sensor/channel in NI MAX with a controlled, safe stimulus.

Position is constant, wrong by a factor, or reversed

  • Confirm the controller analog output and Module 2 input wiring.
  • Scale 0 gives a constant Offset. Units text alone performs no conversion.
  • Recalculate scale/offset from two endpoints; a reversed transfer needs negative scale.
  • Validate at an independent known position and confirm the signal remains within ±10 V.

Meter is red

Read the numeric peak and compare it with the expected physical range. Red only means above 80% of the user-selected meter full scale. Raise the display full scale if appropriate, but separately inspect waveforms for flat tops and compare sensor/module electrical limits. The meter is not a clipping alarm.

Noise, offsets, or spikes

Check mounting, grounding, cable strain, connector seating, nearby interference, sensor/controller warm-up, and range. Compare a stationary baseline with NI MAX. Preserve suspicious raw data and document the condition rather than filtering it silently during acquisition.

Files and storage

No file appears immediately

A file is reported after a complete block is acquired and written. With a 10 s block, wait more than 10 s. Check State/status bar and the configured path.

Cannot write output

Use an existing parent path for which you have permission, avoid invalid prefix/path characters, and verify free space. Prefer a local disk; network/removable storage can add latency or disconnect. Previously completed files remain usable after a later write error.

HDF5 will not open in a text editor

This is expected. Use h5py, MATLAB, HDFView, or h5dump. If h5py is missing, reinstall the package dependencies.

CSV timestamps look rounded

Spreadsheet display precision is often insufficient for large epoch values. Read as float64 in Python/MATLAB and subtract the first timestamp, or reconstruct relative time from sample index and actual sample rate.

GUI settings are stale or do not restore

Settings save on Start and normal close through Qt QSettings. On Windows they normally reside under HKEY_CURRENT_USER\Software\vibetest\daq. Before clearing them, record needed calibration and configuration. A force-killed process may not save the most recent edits.

Escalating a problem

Provide: software commit/version, Python and NI-DAQmx versions, chassis/module models and NI MAX names, exact command or screenshots of settings, enabled channels, full error text/code, whether NI MAX self-test works, and a small example output if safe to share. Never include controlled or sensitive test data without authorization.
